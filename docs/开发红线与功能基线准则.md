# 开发红线与功能基线准则

> **执行等级**：最高优先级 (P0 绝对铁律)  
> **适用对象**：所有参与 O-Maid 项目的代码开发、AI 编程助手及协同人员

---

## 1. 核心铁律：功能零删减原则 (Zero Feature Regression)

1. **不可削减已有入口**：
   - 严禁以“界面优化”、“排版精简”、“追求现代感”等任何理由，私自隐藏、挪移或删除已有功能按钮。
   - 特别针对插件 Header 顶部的 **7 大常驻按钮**，必须无条件常驻显示：
     - **`👤`**（云端账号）
     - **`⚙️`**（系统设置）
     - **`◀`**（折叠侧边栏）
     - **`📤`**（导出规则 JSON）
     - **`📥`**（导入规则 JSON）
     - **`＋`**（新建规则选择卡）
     - **`✕`**（关闭面板）
2. **快捷入口保护**：
   - 本地库列表中的 **`[+ 新建引导]`** 与 **`[+ 新建提示]`** 为核心高频入口，严禁随意移除。
3. **状态机安全**：
   - 任何视图切换逻辑（如打开设置、账号、编辑器后返回主界面），必须保证主界面的按钮显示状态完整恢复，绝不允许因状态覆盖导致按钮永久处于 `display: none`。

---

## 2. 变更流程规范：文档先导与审核制

1. **构思与文档先行**：
   - 在着手任何设计或修改代码前，若涉及功能增删或重大交互变更，必须首先在相关功能规格文档中更新方案。
2. **提请审核确认**：
   - 将变更点与影响范围明确告知用户，获得用户的明确批准后，方可分解任务着手编码。
3. **分步渐进落地**：
   - 禁止一次性大包大揽全面颠覆式重构，遵循“小步快跑、逐个验证”原则。

---

## 3. 技术设计规范：遵循 KISS 原则

1. **拒绝过度工程化**：
   - 保持架构简洁，不引入不必要的设计模式、冗余抽象层或复杂的第三方框架。
   - 插件界面基于原生 Web 标准与 Shadow DOM 即可实现极佳体验。
2. **立足事实与测试自验**：
   - 代码编写完毕后，必须以事实为准绳进行自验（启动后端测试接口、通过浏览器查看真实效果），严禁假设与盲目承诺。
3. **存储与通信红线**：
   - 涉及全局用户状态、配置数据，一律采用 `chrome.storage.local`，绝不可再使用按 Origin 隔离的 `localStorage`。
