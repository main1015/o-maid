# O-Maid 云端共享版本 (Multiplayer) 需求文档 (PRD)

## 1. 产品背景与目标
现有的 O-Maid 是一个“单机版”的 Chrome 扩展，用户的页面引导（Guided Tours）和悬停提示（Hover Hints）只能在本地使用。
为了让优秀的引导流程能够在团队内部或更广泛的用户群中共享，我们计划开发**云端共享版本 (Multiplayer)**。

**核心目标：**
- **建立共享生态**：允许用户将本地创建的引导和提示发布到云端。
- **一键发现与使用**：其他用户在访问相同网站（域名）时，可以轻松发现并下载这些共享规则。
- **轻量级实现**：初期以快速验证模式为主，提供简单易用的账号系统和共享界面。

## 2. 核心功能描述

### 2.1 云端账号体系
- **功能说明**：用户需要注册并登录账号，才能发布规则至云端。
- **关键操作**：
  - **注册**：输入用户名和密码即可创建账号（极简模式，无需邮箱验证）。
  - **登录**：输入凭证换取身份令牌（JWT），保持登录状态。
  - **登出**：清除本地的身份令牌。
- **限制**：未登录用户只能浏览和下载云端规则，不能发布。

### 2.2 规则发布 (Publish)
- **功能说明**：用户可以将本地创建的 Guide 或 Hint 上传至服务器。
- **数据结构要求**：
  - 必须绑定当前规则适用的**域名 (Domain)**。
  - 必须记录规则的**创建者 (Author)**。
- **交互流程**：
  - 在插件侧边栏的“本地库”列表中，每个用户自定义的规则旁提供一个「发布 ☁️」按钮。
  - 点击后，调用后端 API 上传 JSON 数据，并在界面提示成功/失败。

### 2.3 云端发现与下载 (Discover & Download)
- **功能说明**：智能匹配当前网页的共享规则，供用户选择使用。
- **交互流程**：
  - 侧边栏新增「云端发现」选项卡。
  - 当用户切换到此选项卡时，插件提取当前页面的域名（如 `github.com`），向后端请求该域名下的所有共享 Guide 和 Hint。
  - 列表展示规则名称、作者、下载量等信息。
  - 用户点击「下载 ⬇️」按钮，将规则复制一份保存到本地 `chrome.storage.local` 中，后续即可在本地库直接触发。

### 2.4 云端已同步数据刷新 (Sync Refresh)
- **功能说明**：支持一键检查并更新本地已关联云端的规则（已下载的云端规则、或已成功发布同步的规则），使本地即时同步云端的最新变更（如步骤文本更新、选择器修正、最新下载量与作者变更等）。
- **交互与业务规则**：
  - 在插件侧边栏的“本地规则库”视图工具栏提供「🔄 刷新同步」操作入口。
  - 扫描本地所有包含 `cloudId` 的 Guide 与 Hint，批量比对并请求云端最新快照。
  - 保留本地的自身标识与创建时间，原子化覆写名称、步骤/文案、选择器、作者及下载量等信息。
  - 刷新完成后提供轻量 Toast 提示更新项数，并无感刷新当前列表。

### 2.5 数据存储与追踪
- **后端数据库需求**：
  - `Users` 表：存储用户信息及加密后的密码、角色（admin/user）。
  - `Guides` 表：存储共享的引导流程、关联的域名、作者外键、`downloads` 下载量。
  - `Hints` 表：存储共享的悬停提示、关联的域名、作者外键、`downloads` 下载量。
- **统计功能**：每次有用户“下载”一个 Guide 或 Hint 时，后端的 `downloads` 计数器自增 1，并在平台概览中累计全局总下载量。

### 2.5 Web 可视化管理控制台 (Web Dashboard)
- **功能说明**：为后端服务提供一体化内置的 Web 管理控制台，服务启动后直接访问根路径（`http://localhost:<端口>/`）即可使用。
- **核心模块**：
  - **平台概览看板**：直观呈现创作者总数、云端任务总数、提示总数及全网累计下载安装人次（引导+提示）；提供最新发布动态信息流。
  - **引导任务管理**：支持跨域名检索所有引导任务，支持点击“详情”唤出模态框查看具体引导步骤（Step 文本与 CSS 选择器），展示下载量与作者，支持录入新任务与一键删除任务。
  - **悬停提示管理**：按网址或文案检索全部悬停提示，展示文案、选择器、作者、下载量（🔥 次数徽章），支持录入与一键删除。
  - **用户账号管理**：支持注册新用户、用户列表全景查询、重置用户密码、注销/删除用户。
  - **系统监控与 API 控制台**：显示服务端 Node 版本、运行时间、内存负载等；内置开放 API 接口文档。

## 3. 功能基线与不可删减红线 (Non-negotiable Baseline)
详见详细基准文档：[开发红线与功能基线准则.md](./开发红线与功能基线准则.md)、[插件端功能规格说明书.md](./插件端功能规格说明书.md)、[Web控制台功能规格说明书.md](./Web控制台功能规格说明书.md)。
- **不可删减原则**：
  - 严禁以“界面精简”、“优化视觉”等任何名义私自删减、隐藏、挪动已有功能入口（包括 Header 的 7 大常驻按钮：`👤` 账号、`⚙️` 设置、`◀` 折叠、`📤` 导出、`📥` 导入、`＋` 新建、`✕` 关闭，以及本地库各分组的快捷新建按钮）。
- **交互与存储规范**：
  - 必须采用 `chrome.storage.local` 存储所有用户登录态与全局配置，确保跨页面、跨标签页实时保持一致。
  - 引导和悬停提示的录入以插件端屏幕拾取为主，Web 后台主要负责全盘监控、审核、修改密码与数据下架。

## 4. 非功能性需求
- **性能**：云端发现功能应设计为“按需加载”（只有用户点击 Tab 或特定按钮时才去请求服务器），避免每次页面加载都产生网络请求，从而保证插件的极速体验。
- **兼容性**：现有的本地存储数据结构需要保持向后兼容，仅增加用于标识云端来源的字段（如需要）。
- **扩展性**：后端架构需支持未来平滑迁移至云服务（如 Supabase、AWS 等）或支持更复杂的鉴权（OAuth）。

## 4. 后续规划 (Phase 2)
1. **点赞与评论**：允许用户对有用的引导点赞。
2. **私有分享**：通过提取码（Share Code）在小团队内部分享，不公开到大厅。
3. **可视化编辑器更新**：在分享前，允许用户预览自己将要分享的内容。
